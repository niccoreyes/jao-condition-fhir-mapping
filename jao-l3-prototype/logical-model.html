Source element hierarchy

Expand a section to see its row-specific fields. Labels and definitions come from the workbook. Names are locally normalized to camelCase for the StructureDefinition. Datatypes and 0..1 cardinalities are proposals, not requirements asserted by the source.

WHO completion criteria: current status

The prototype makes missing inputs visible instead of treating a generated JSON file as publication-ready.

Covered: one tab, one model

All 34 populated clinical rows occur once under their 13 worksheet sections. Repeated complication fields retain separate source identifiers.

Covered: local traceability

Each source field has an element code and Excel row mapping. These codes identify local worksheet rows, not globally governed clinical concepts.

Pending: common/WHO concept IDs

Match concepts to an approved common glossary or WHO SMART identifiers where applicable. Request new definitions if none exists. No WHO identifier is assigned here.

Pending: cardinality and datatype

Source sheet gives no explicit required/repeat rules. Review the provisional 0..1 and typed choices, particularly co-morbidities, binary questions, and asthma evidence.

Pending: answer sets

Workbook Terminology Binding cells are blank. Define or reuse governed ValueSets for coded questions/classifications only after answer options and versioning are agreed.

Pending: semantic mapping

Current crosswalk supplies proposed resource paths and unresolved questions. Approve distinctions such as diagnosis time, negative answers and death cause before formal maps or transformations.

Pending: publication checks

WHO Starter Kit 2.0.0 describes an R5-based CRMI publication process. This prototype uses PH Core's R4 4.0.1 base and does not claim CRMI profile conformance.

Pending: stewardship

Assign clinical and terminology owners, resolve DETECTED ISSUE grouping, track approvals and version changes before assigning an authoritative canonical.
